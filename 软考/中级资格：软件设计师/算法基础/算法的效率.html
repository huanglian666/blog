算法的效率

1. 考点：概述

1.1 基本概念

  • 时间复杂度： 是指程序运行从开始到结束所需要的时间。

    • 分析方法：通常分析时间复杂度的方法是从算法中选取一种对于所研究的问题来说是基本运算的操作，以该操作重复执行的次数作为算法的时间度量。
    • 一般来说，算法中原操作重复执行的次数是规模 nnn 的某个函数 T(n)T(n)T(n)。

  • 空间复杂度：是指对一个算法在运行过程中临时占用存储空间大小的度量。

    • 一个算法的空间复杂度只考虑在运行过程中为局部变量分配的存储空间的大小。

1.2 思考与案例

  • 思考：求 1+2+⋯+1001+2+\cdots+1001+2+⋯+100 的哪个算法更快？占用空间更少？

  • 算法1：​int i = (1+100)*100/2;

    • 只要运算 1 次。
    • 需要 1 个变量。

  • 算法2：​for 循环执行 100 次。

    • 要运算 nnn 次。
    • 需要多个变量。

1.3 渐进时间复杂度

  • 引入原因：由于许多情况下要精确计算 T(n)T(n)T(n) 是困难的，因此引入了渐进时间复杂度在数量上估计一个算法的基本操作总数。一般讲时间复杂度，就是指渐进时间复杂度。
  • 定义：如果存在两个常数 ccc 和 mmm，对于所有的 nnn，当 n≥mn \ge mn≥m 时有 f(n)≤cg(n)f(n) \le cg(n)f(n)≤cg(n)，则有 f(n)=O(g(n))f(n) = O(g(n))f(n)=O(g(n))。也就是说，随着 nnn 的增大， f(n)f(n)f(n) 渐进地不大于 g(n)g(n)g(n)。

1.4 示例与度量

  • 例如：一个程序的实际执行时间为 T(n)=3n3+2n2+nT(n) = 3n^3 + 2n^2 + nT(n)=3n3+2n2+n，求其渐进时间复杂度。

  • 随着 nnn 不断增加，2n2+n2n^2 + n2n2+n 的影响很小。时间主要由 n3n^3n3 决定，则 T(n)T(n)T(n) 的渐进时间复杂度就是 O(n3)O(n^3)O(n3)，把常量值去掉。

  • 常见的对算法执行所需时间的度量：

    O(1)<O(log⁡2n)<O(n)<O(nlog⁡2n)<O(n2)<O(n3)<O(2n)<O(n!)O(1) < O(\log_2 n) < O(n) < O(n \log_2 n) < O(n^2) < O(n^3) < O(2^n) < O(n!) O(1)<O(log2​n)<O(n)<O(nlog2​n)<O(n2)<O(n3)<O(2n)<O(n!)

2. 考点：实例讲解

    • 如：​k = 0;

  • 整个程序都只有顺序执行的语句，没有循环语句，或复杂函数的调用

void main() {

void main() {

2.3 时间复杂度 O(n2)O(n^2)O(n2)

  • 双层循环
void main() {
    int i, s = 0, n = 1000;
    for(i = 1; i < n; i++)

2.4 O(n3)O(n^3)O(n3) 依次类推：也就是三层循环了

2.5 时间复杂度 O(log⁡2n)O(\log_2 n)O(log2​n)

  • 在有序数组中实现折半查找
int search(int array[], int n, int v)
{
    int left, right, middle;
    left = 0, right = n - 1;
    while (left <= right)
    {
        middle = (left + right) / 2;
        if (array[middle] > v)
        {
            right = middle - 1;
        }
        else if (array[middle] < v)
        {
            left = middle + 1;
        }
        else
        {
            return middle;
        }
    }
    return -1;
}

  • 核心思想：每次查找，范围减半

    • 折半查找的原理是：每次拿数组中间的元素 ​array[middle] 和目标值 vvv 比较：

      • 如果目标值小，就去左半区找。
      • 如果目标值大，就去右半区找。
      • 如果相等，直接返回。

    • 无论去左半区还是右半区，待查找的元素数量都会瞬间减少一半。

  • 数学推导过程

    • 假设数组一共有 nnn 个元素。
    • 第 1 次查找后，剩余元素最多为 n2\frac{n}{2}2n​ 个。
    • 第 2 次查找后，剩余元素最多为 n22\frac{n}{2^2}22n​ 个。
    • 第 3 次查找后，剩余元素最多为 n23\frac{n}{2^3}23n​ 个。
    • ……
    • 第 kkk 次查找后，剩余元素最多为 n2k\frac{n}{2^k}2kn​ 个。
    • 最坏的情况是：一直找到最后只剩 1 个元素才找到（或者发现找不到）。
    • 所以，当剩下 1 个元素时：n2k=1\frac{n}{2^k} = 12kn​=1
    • 两边同时乘以 2k2^k2k：n=2kn = 2^kn=2k
    • 两边取以 2 为底的对数：k=log⁡2nk = \log_2 nk=log2​n
    • 这就意味着，最多只需要查找 log⁡2n\log_2 nlog2​n 次，就能把范围缩小到 1 个元素。因此，时间复杂度是 O(log⁡2n)O(\log_2 n)O(log2​n)。

  • 举个直观的例子

    • 假设 n=8n = 8n=8：

      • 第 1 次查找，剩 4 个元素 (8÷28 \div 28÷2)
      • 第 2 次查找，剩 2 个元素 (4÷24 \div 24÷2)
      • 第 3 次查找，剩 1 个元素 (2÷22 \div 22÷2)
      • 结束。最多找了 3 次。

    • 而 log⁡28=3\log_2 8 = 3log2​8=3，完全吻合。

2.6 时间复杂度 O(nlog⁡2n)O(n \log_2 n)O(nlog2​n)

  • 典型代表：堆排序（利用大小顶堆实现排序）、快速排序、归并排序。

  • 推导与理解逻辑：

    • 每次重建堆（或分治合并）的时间复杂度是 log⁡2n\log_2 nlog2​n，nnn 个元素基本上就是 nlog⁡2nn \log_2 nnlog2​n。
    • 每次从堆顶取出最大/最小元素后，需要重建堆。重建堆本质上是把根节点向下调整，调整的次数取决于树的高度，而 nnn 个节点的完全二叉树高度为 log⁡2n\log_2 nlog2​n。
    • 一共要取 nnn 次，所以总时间复杂度是 n×log⁡2n=O(nlog⁡2n)n \times \log_2 n = O(n \log_2 n)n×log2​n=O(nlog2​n)。

2.7 时间复杂度 O(2n)O(2^n)O(2n)

  • 典型代表：判断是否包含指定子序列、LCS（最长公共子序列）、钢管切割问题、暴力求所有子集，动态规划法自顶向下，时间复杂度都为 O(2n)O(2^n)O(2n) 。

  • 【判断是否包含指定子序列】例子： a,b,ca, b, ca,b,c数学计算与含义解析：

    • 这代表了“选或不选”的决策过程。

    • 假设有 3 个元素 a,b,ca, b, ca,b,c。我们要找出它所有的子集（或者判断它是否包含某个特定子序列）。对于每一个元素，我们都有 2 种选择：

      • 选它（状态记为 1）
      • 不选它（状态记为 0）

    • 那么：

      • 对于元素 aaa：有 2 种选择
      • 对于元素 bbb：有 2 种选择
      • 对于元素 ccc：有 2 种选择

    • 根据乘法原理，总共可能的情况就是：2×2×2=23=82 \times 2 \times 2 = 2^3 = 82×2×2=23=8 种。

    • 推广到 nnn 个元素：

      • 如果这里有 nnn 个元素，每个元素都有“选”和“不选”两种可能，那么总的计算量就是 nnn 个 2 相乘，即 2n2^n2n。
      • 这就是指数级时间复杂度 O(2n)O(2^n)O(2n) 的数学来源。

  • 【钢管切割的问题】经典案例：钢管切割问题（Rod Cutting Problem）

    • 问题描述：假设你有一根长度为 nnn 的钢管，和一个价格表 p[i]p[i]p[i]（表示长度为 iii 的钢管能卖多少钱）。目标是如何切割这根钢管，使得卖出的总价格最高？

    • 举例说明（钢管长度 n=4n=4n=4）：

      • 价格表：长度 1→11 \rightarrow 11→1 元，长度 2→52 \rightarrow 52→5 元，长度 3→83 \rightarrow 83→8 元，长度 4→94 \rightarrow 94→9 元。

      • 切法与收益：

        • 不切：卖 999 元
        • 切 1 和 3：1+8=91 + 8 = 91+8=9 元
        • 切 2 和 2：5+5=105 + 5 = 105+5=10 元（✅ 最优解）
        • 切 1, 1, 2：1+1+5=71 + 1 + 5 = 71+1+5=7 元
        • 切 1, 1, 1, 1：1+1+1+1=41 + 1 + 1 + 1 = 41+1+1+1=4 元

    • 为什么暴力递归是 **O(2n)O(2^n)O(2n)**​ ？

      • 决策过程：

        • 对于长度为 nnn 的钢管，第一刀可以切在任意位置 iii（1≤i≤n1 \le i \le n1≤i≤n）。
        • 切下长度为 iii 的一段，剩下的部分长度是 n−in-in−i，剩下的部分又面临同样的子问题。
        • 递归公式：MaxProfit(n)=max⁡1≤i≤n(p[i]+MaxProfit(n−i))\text{MaxProfit}(n) = \max_{1 \le i \le n}(p[i] + \text{MaxProfit}(n-i))MaxProfit(n)=max1≤i≤n​(p[i]+MaxProfit(n−i))。

      • 递归树结构（以 n=4n=4n=4 为例）：

      • 为什么是指数级？

        • n=1n=1n=1 时，1 种切法（不切）
        • n=2n=2n=2 时，2 种切法（不切 / 切1+1）
        • n=3n=3n=3 时，4 种切法
        • n=4n=4n=4 时，8 种切法
        • ……
        • 当长度为 nnn 时，总共有 2n−12^{n-1}2n−1 种切法。
        • 这就是指数爆炸。当 n=40n=40n=40 时，2392^{39}239 就已经超过 5000 亿了，计算机根本算不过来。

      • 关键问题：重复子问题（Overlapping Subproblems）

        • 递归树里的 f(2)f(2)f(2) 被计算了很多次，f(1)f(1)f(1) 更是被反复计算。这种重复子问题就是暴力递归效率极低的根本原因。
        • 总结：通过切法总数推导可知，其暴力递归的时间复杂度是 O(2n−1)O(2^{n-1})O(2n−1)（在渐进意义上即为 O(2n)O(2^n)O(2n)）。

  • 【动态规划算法自顶而下】例子：树形结构图与决策树 / 子集树解析：

    • 这是一个没有画完的树状草图，它对应了左边 a,b,ca, b, ca,b,c 的决策过程：

      • 第一层：对应元素 aaa。树从这个根节点开始，分出两条分支（左分支代表“选 aaa”，右分支代表“不选 aaa”）。
      • 第二层：对应元素 bbb。第一层分出的每个节点，又各自分出两条分支。
      • 第三层：对应元素 ccc。第二层分出的每个节点，再次各自分出两条分支。

    • 草图结构演示：

    • 				 (根)               
                /    \        
           选a /      \ 不选a 
              /        \          
         (节点1)      (节点2)          
         /    \        /    \     
    选b /      \不选b/      \不选b        
       /        \   /        \     
   (节点3)  (节点4)(节点5)  (节点6)      
    /  \     /  \   /  \     /  \    
   ...  ... ... ... ... ... ... ...  (继续对 c 进行分支)

    • 为什么这个树能解释 O(2n)O(2^n)O(2n)？

      • 树的深度是 nnn（对应 nnn 个元素）。
      • 每一层节点的数量都会翻倍：第一层 1 个，第二层 2 个，第三层 4 个，第四层 8 个……
      • 到了第 nnn 层，节点的数量就是 2n−12^{n-1}2n−1 个左右。
      • 如果要遍历整棵树（也就是找出所有可能的子集），算法需要访问的节点总数接近 2n+1−12^{n+1}-12n+1−1，这在数量级上也就是 O(2n)O(2^n)O(2n)。

2.8 常见时间复杂度的大小（快慢）关系与排序

O(1)<O(log⁡2n)<O(n)<O(nlog⁡2n)<O(n2)<O(n3)<O(2n)<O(n!)O(1) < O(\log_2 n) < O(n) < O(n \log_2 n) < O(n^2) < O(n^3) < O(2^n) < O(n!) O(1)<O(log2​n)<O(n)<O(nlog2​n)<O(n2)<O(n3)<O(2n)<O(n!)

  • 左边是效率高（快），右边是效率低（慢）。

  • 重点理解记忆倒数三个（图里用红字标注的重点）：

    • O(2n)O(2^n)O(2n)：指数级。比如求所有子集，每增加一个元素，计算量翻倍。nnn 稍微大一点程序就跑不动了。
    • O(na)O(n^a)O(na)：多项式级，通常指 a>2a > 2a>2 的情况。比如 O(n3)O(n^3)O(n3)，多层嵌套循环。
    • O(n!)O(n!)O(n!)：阶乘级。最典型的代表是旅行商问题（TSP）的暴力穷举解法，比如全排列问题。n=10n=10n=10 时，计算量就超过 300 万次了。

2.9 考试快速记忆与对应表

  • 看循环次数：

    • 单层循环 →O(n)\rightarrow O(n)→O(n)
    • 双层嵌套循环 →O(n2)\rightarrow O(n^2)→O(n2)
    • 三层嵌套 →O(n3)\rightarrow O(n^3)→O(n3)
    • 每次循环范围减半（如二分） →O(log⁡n)\rightarrow O(\log n)→O(logn)
    • 循环里带二分，或者分治合并 →O(nlog⁡n)\rightarrow O(n \log n)→O(nlogn)

  • 经典算法对应表（直接背）：

    • 二分查找：O(log⁡n)O(\log n)O(logn)
    • 冒泡 / 插入 / 选择排序：O(n2)O(n^2)O(n2)
    • 快速排序 / 归并排序 / 堆排序：O(nlog⁡n)O(n \log n)O(nlogn)
    • 暴力求所有子集：O(2n)O(2^n)O(2n)
    • 暴力求全排列：O(n!)O(n!)O(n!)

【解析】

本题考察的是最长公共子序列（LCS）算法的时间复杂度分析。

  • 第一空（蛮力法） ：
    序列 XXX 的长度为 nnn，其所有可能的子序列个数为 2n2^n2n（每个元素有选或不选两种状态）。对于 XXX 的每一个子序列，都需要去判断它是否也是 YYY 的子序列，这个判断过程最坏情况下需要遍历 YYY，时间复杂度为 O(n)O(n)O(n)。因此，蛮力法的总时间复杂度为 O(n⋅2n)O(n \cdot 2^n)O(n⋅2n)。对应选项为 D。
  • 第二空（动态规划/自底向上法） ：
    根据题目给出的状态转移方程，采用自底向上的方法（通常指填表法）实现该算法时，需要计算一个二维数组 C[i][j]C[i][j]C[i][j]，其中 iii 的范围是 000 到 nnn，jjj 的范围也是 000 到 nnn。这个二维表格的大小为 (n+1)×(n+1)(n+1) \times (n+1)(n+1)×(n+1)，即包含 O(n2)O(n^2)O(n2) 个状态（单元格）。计算每一个状态 C[i][j]C[i][j]C[i][j] 时，只需要进行常数次的比较和赋值操作（O(1)O(1)O(1) 的时间）。因此，总的时间复杂度等于状态数量乘以单个状态的计算时间，即 O(n2)×O(1)=O(n2)O(n^2) \times O(1) = O(n^2)O(n2)×O(1)=O(n2)。对应选项为 A。
